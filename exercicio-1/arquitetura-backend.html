Exemplo prático: cadastro e uso de looks no projeto Dighanger.com

1. O papel do backend na arquitetura cliente-servidor

Na arquitetura cliente-servidor, o cliente (navegador ou app) solicita serviços e o servidor os fornece. O backend é a parte da aplicação que roda no servidor e que o usuário nunca vê: ele concentra as regras de negócio e o acesso aos dados.

No Dighanger.com, o frontend mostra a tela “Meus Looks”, mas é o backend que:

  • Recebe pedidos como “cadastrar o Look 3” ou “registrar que usei o Look 5 hoje”;
  • Valida os dados (o look existe? a data é válida? a cor foi informada?);
  • Autentica e autoriza o usuário (cada pessoa só altera o próprio guarda-roupa);
  • Aplica regras de negócio (ao registrar um uso, incrementar o contador de vezes usado e atualizar a data do último uso);
  • Persiste e consulta o banco de dados;
  • Responde ao cliente com dados (normalmente JSON) e um código de status.

2. Fluxo completo de uma requisição

Passo a passo (exemplo: registrar o uso do Look 5)

  1. O usuário clica em “Usei hoje” no frontend.
  2. O navegador resolve o domínio (DNS) e envia uma requisição HTTP ao servidor.
  3. O backend recebe a requisição, identifica a rota e verifica o token de autenticação.
  4. Valida o corpo ({"data": "2026-11-07"}) e aplica as regras de negócio.
  5. Consulta/grava no banco de dados (insere o uso e incrementa o contador do look).
  6. O banco devolve o resultado ao backend.
  7. O backend serializa a resposta em JSON com o status HTTP adequado (201 Created).
  8. O frontend recebe a resposta e atualiza a tela.

3. Como o backend processa requisições HTTP

Uma requisição HTTP possui método, URL, cabeçalhos e, às vezes, corpo:

POST /looks/5/usos HTTP/1.1
Host: api.dighanger.com
Content-Type: application/json
Authorization: Bearer <token>

{"data": "2026-11-07"}
  1. Roteamento: o backend associa método + caminho a uma função (ex.: POST /looks/{id}/usos).
  2. Middlewares: autenticação, CORS, registro de logs.
  3. Validação: verifica tipos e campos obrigatórios; se inválido, responde 422/400.
  4. Lógica de negócio: executa a regra (incrementar o contador de usos).
  5. Acesso a dados: executa as consultas no banco.
  6. Resposta: status (200, 201, 404, 500…), cabeçalhos e corpo JSON.

5. O papel das APIs no desenvolvimento backend

A API (Application Programming Interface) é o contrato que define como o frontend (ou qualquer outro sistema) conversa com o backend, sem conhecer seus detalhes internos.

  • Desacopla frontend e backend: o mesmo backend atende site, app móvel e integrações.
  • Padroniza a comunicação (URLs, métodos, formato JSON, códigos de status).
  • Protege o banco: o cliente nunca acessa o banco diretamente, só passa pela API.
  • Documenta os recursos: ex. GET /looks, POST /looks, POST /looks/{id}/usos.

Em APIs REST, cada recurso (look, uso) tem uma URL e é manipulado pelos métodos HTTP (GET, POST, PUT, DELETE).
